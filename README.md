# 月日（つきひ）— 最小構成モック

月経前障害（PMS・PMDD）の受診判断を支援する記録の仕組み。SPLアカデミー AY26/27、山本裕子さんのプロジェクトの試作。

## これは何か

月経前後の不調を毎月繰り返しながら、市販薬や休みの確保でやり過ごし、婦人科を受診していない女性が、自分の不調が治療の対象になりうるかを判断し、受診するかどうかを決めるための手がかりを得る。それだけを行う。

診断はしない。記録やウェアラブルのデータから PMS・PMDD を判定しない。

## なぜ最小構成なのか

当事者8名へのインタビューで、毎日記録している人は0名だった。理由は負担ではなく、周期の把握には月経開始日だけで足りるからである。PMDD の診断に必要な DRSP（2周期の毎日の記録）を経験した人も0名だった。

診断側が求める記録と、受診前の人が実際にできる記録のあいだには段差がある。アプリがその段差を一気に埋めようとすると続かない。そこで、受診前は「つらかった日だけ」、受診が決まってから毎日の記録に切り替える二段構えにした。

## 画面

| 画面 | 入力 | 役割 |
|---|---|---|
| ホーム | 今日の調子（3択・1タップ）、月経開始日（ボタン1つ） | 記録。つけたい日だけ |
| ふりかえり | なし | 2周期を月経開始日で重ね、つらい日の位相を見せる。続き具合（記録率、最長の空白、夜間装着率）も出す |
| 受診の準備 | なし | 医師に見せる1枚。ここから毎日の記録と受診結果の入力へ |
| 毎日の記録 | DRSP 相当 14 項目・4段階 | 受診が決まった人の二段目。2周期（56日）で診断に使える |
| 受診のあと | 選択式4問 | 行った先、言われたこと、出た薬、次の予約。受診結果を記録に戻す |
| 1分の確認 | 4問 | 記録に進むかどうかの入口 |

入口は一日一タップのまま、出口を三つ足してある。毎日の記録は、受診前の一タップと、診断側が求める 14 項目の落差をそのまま見せるために、あえて同じアプリの中に置いた。

## 設計の根拠

PSST と DRSP を同一集団で比較した研究では、両者の判定は一致せず（Kappa 0.12）、PSST の感度 79%、特異度 33.3% だった（Henz 2018, doi:10.1055/s-0037-1608672）。質問票は診断ではなく入口として使う。この二つの数字は「1分の確認」の結果画面にそのまま書いてある。

質問票は日本で開発された PSQ に差し替えるのが筋である（Takeda 2020, doi:10.2147/IJWH.S269392）。モックの4問は仮のもの。

HRV は画面から外した。位相の推定には見込みがあるが、症状の判定に使った報告は群間比較にとどまる（Brown 2024, doi:10.3389/fpsyt.2024.1448914）。

## 既知の不足

- ふりかえりと続き具合の数字は例として埋め込んだもの。入力からは計算していない。本人のインタビューに合わせて差し替える
- 1分の確認の4問は仮。PSQ の実項目に差し替える
- 受診結果はブラウザの中だけで、どこにも送っていない。実装では同意と保存先の設計が要る
- 相談先の一覧は空欄のまま
